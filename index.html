Why Pro includes termorq-cli

Same engine

termorq-cli calls through the app library. A check that fails in the terminal fails in CI.

Secrets stay out of the file

The workspace stores a name and a vault reference. The value arrives as AIT_SECRET_… or from Azure Key Vault or 1Password.

A result your forge already understands

Text for a person. JSON or YAML for a script. JUnit for GitHub, GitLab, and Azure DevOps.

Five things worth learning first

1

One prompt for four kinds of work

Type a shell line, @endpoint, @tool, or @chat. The scrollback marks which one ran, how long it took, and the HTTP status.

2

A collection is a runbook

Favourites run first. Captures fill {{name}} on later lines. A failed check, a non-zero exit, or Ctrl+C stops the run in the app.

3

Secrets are not in the git diff

Keys go to the OS keychain. A team folder keeps akv:// and op:// references. Save refuses a file that still contains a token.

4

Pro termorq-cli is that runbook, headless

Every subcommand, the secret rules, and a pipeline for GitHub, GitLab, and Azure DevOps.

5

A workspace your team can review

@workspace save writes pretty JSON under .ai-terminal/. You commit the diff yourself. The app does not push.
