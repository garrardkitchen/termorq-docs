    Calling an endpoint

    @create endpoint asks for the connection, the name, the method, and the path. Methods are GET, POST, PUT, PATCH, DELETE, HEAD, and OPTIONS. You can add query defaults, path parameters, and extra headers.

    A {name} in the path becomes a path parameter with an optional default. Call it with --name value.

    @create endpoint

    Names may contain spaces. Tags show as chips. Type a tag and press Enter, , or Tab to add it; pasting a list such as invoices, writes adds each one. While the field has focus, a list suggests tags already used on your other endpoints, most used first; type to filter it, then pick one with ↑ ↓ and Enter or a click. Backspace in an empty field removes the last chip, and × removes any chip. Esc closes the suggestions first; a second Esc closes the form. Repeats are ignored whatever their case, a tag can be up to 60 characters, and an endpoint can have up to 20. The first tag is the group the endpoint sits in, in the Library and in @endpoint. Endpoints saved before tags existed show under Untagged until you add one or import again. POST, PUT, and PATCH can include a JSON body, sent as application/json. A blank body sends none. The test shows the status as a coloured pill. For a new endpoint, Save stays disabled until an HTTP response comes back. When you edit a saved one, Save is enabled as soon as you change a field; testing first is optional.

    {{variable}} anywhere in the path, query, headers, or body is filled from Settings → Environments for the connection’s environment. An unknown variable stops the call. These variables are not secrets. A secret belongs on the connection or in a vault reference.

    List and call link

    @endpoint opens that list in the prompt block, under the line you are typing. The line is the filter.

    On its own the list has three sections: Recent (the endpoints you called last), ★ Favourites, and APIs, with each API connection as a folder. Press Tab or Enter on a folder to fill in api:"<name>" and list that API’s endpoints. The star on a row marks or clears a favourite. Endpoint rows in @apis use the same star.

    Type the start of a name to list the names that start with it, favourites first, then A→Z. Tab cycles them and → accepts the ghost text. The matching letters in the name are underlined.

    Search with filter words link

    Filter words narrow the list. Whatever else you type is matched fuzzily, the way Ctrl+R matches history, against the name, the path, the API name, and the tags. Letters that match the name are underlined. Endpoints you called recently rank a little higher.

    WordKeeps
    api:billingEndpoints whose API connection name contains billing. Quote a name with spaces: api:"Billing API"
    tag:invoicesEndpoints with a tag that contains invoices. tag:untagged keeps endpoints with no tag
    method:post, or just postThat HTTP method. get, post, put, patch, delete, head, and options work on their own
    is:favFavourites
    is:graphqlGraphQL endpoints
    env:prodEndpoints whose API connection is in a matching environment
    customer:contosoEndpoints whose API connection is for a matching customer
    @endpoint api:billing method:post inv
@endpoint api:"Service Desk API" tag:tickets
@endpoint is:fav get

    Different words must all match. Two words of the same kind, such as api:billing api:identity, match either. The section label above the results names the filters, for example Billing API · POST · best match. Enter on a result opens its call form, filled in with the saved defaults; it never calls straight away. Tab inserts @endpoint <name> instead. Both drop the filter words. The Library’s Endpoints search uses the same words: ↑ ↓ move the highlighted result, and Enter opens its call form.

    Call link

    @endpoint
@endpoint List users
@endpoint Get user --id 1
@endpoint List users --query status=active --query limit=20

    @endpoint name on its own opens the call form, with the saved path, query, and body values filled in. Change a value to override it for that call; the saved endpoint is not changed. The form opens with the cursor in its first field (or on Call when the only field is the body), so Enter calls straight away. Enter in any single-line field calls, the same as Call. In the body, Enter adds a new line and Ctrl+Enter (Cmd+Enter on macOS) calls.

    @endpoint name --param value sends straight from the prompt. Flags come after the name. An unknown flag does not call.

    FlagEffect
    --id 1Sets the path or query parameter of that name
    --query key=valueAdds a query parameter for this call, including a key that is not saved. Repeat it. The value is a string. A same-named flag such as --filter wins over --query filter=. A key already in the path’s query string is replaced
    --body {"name":"Ada"}On POST, PUT, or PATCH, replaces the saved JSON for this call. It takes the rest of the line
    --set key=valueChanges one property of the saved body, and adds the key if it is missing. The match ignores case, so totp replaces Totp. Repeat it. The split is the first =. true, false, and null are JSON. Everything else is a string. --set count:=6 forces a JSON number. Quote a value that contains a space
    --set then --body--body replaces the payload, then --set is applied. Put --set before --body on the line

    A value that looks like a secret is masked in @history.

    Confirm before sending link

    GET, HEAD, and OPTIONS only read, so they are always sent without asking. Two settings in Settings → Workspace decide the rest. Both are on by default:

    • Confirm POST calls: POST, PUT, PATCH, any other method that writes, and GraphQL mutations ask first.
    • Confirm DELETE calls: DELETE asks first.

    With a setting off, those calls are sent straight away. With it on, the call asks first, for example Send POST to /invoices?, with Send and Cancel. Send has focus, so Enter sends. Esc or Cancel sends nothing and leaves the call form open, or writes Not sent. under a typed line. Esc closes only the question, not the form or page behind it.

    The question comes up however the call is sent: Call in the form, a typed @endpoint name --param value, a @history re-run, and a Recent or Favourites row (which opens the form first). For a GraphQL endpoint the saved document decides. A query (or a bare { … }) and a subscription send without asking. A mutation, or a document that cannot be read, follows Confirm POST calls and asks Run GraphQL mutation on /graphql?.

    A DELETE started with no parameters opens the call form instead of sending, whatever Confirm DELETE calls says. That covers a bare @endpoint Void invoice, a Recent row, and a @history re-run of a bare line. Fill in the form and press Enter or Call; from there, the DELETE follows the setting. A typed DELETE with parameters, such as @endpoint Void invoice --id 9, follows the setting straight away.

    The scrollback marks the call with an endpoint pill and shows how long it took. The next line is Open in inspector. That link shows the body in the right-hand column, and opens the column if it was hidden. The magnifying glass there searches the body. Search a response has the keys.

    termorq-cli call "@endpoint List users" --workspace ~/src/acme-apis

    API docs link

    @docs <connection> opens markdown docs for one API connection in place of the terminal. It lists the base URL, the auth type, the environment and the customer, then each endpoint grouped by tag: method and path, path and query parameters, headers, a body example, the GraphQL flag, and any response checks.

    @docs Billing API
@docs bill

    A unique start of the name is enough. @docs alone lists the API connections in the prompt block. Preview renders the docs and Raw shows the markdown. Copy copies it. Close or Esc goes back to the terminal. The Docs buttons in the Library open the same view.

    No secret is shown. The connection’s secret, vault reference, and certificate path are left out. Header, parameter, and body values whose names look like credentials (authorization, cookie, token, key, secret, password) are masked.

    GraphQL and streams link

    Tick GraphQL on the endpoint when the body is a query. @sse and @ws stream a saved endpoint. Both are on GraphQL and streams.
